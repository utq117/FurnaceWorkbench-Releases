## 简历精简版

**合炉工作台｜桌面交易辅助与配方求解系统**  
Python / JavaScript / OR-Tools / SQLite / Node.js / Windows

- 设计并交付 Windows 桌面工作台，串联市场材料采集、约束配方求解、持续采购监控与记录查询，提供可安装的版本及更新渠道。
- 采用本地采集与计算、云端账号订阅授权的架构，实现设备管理、账号资料隔离及保留用户凭据的覆盖升级。
- 实现后台任务进度、平台独立限速、挂单去重与交易结果核对；将还价流程纳入持久化状态管理，支持超时取消及重启后的状态恢复。
- 接入大模型辅助反馈摘要和复现信息收集，结合持久化队列、有限重试与人工跟进，形成从用户反馈到版本发布的维护流程。

## 面试时可展开的内容

| 话题 | 可说明的问题 |
| --- | --- |
| 架构取舍 | 为什么高频采集和求解放在本地，授权及反馈放在云端？客户端复杂度如何控制？ |
| 约束求解 | 材料、价格和磨损如何转化为约束？可行解和快照内最优解有什么区别？ |
| 外部系统可靠性 | 请求超时后如何确认交易状态，避免盲目重试？ |
| 桌面产品化 | 如何处理安装依赖、版本升级、用户数据保留和包内容检查？ |
| AI 应用 | 怎样收集必要的复现信息，同时减少用户回答问题的负担？ |
| 发布维护 | 如何把安装包、更新日志、群通知和公告形成可重复的发布流程？ |

项目证据包括公开版本记录、测试数据界面截图与设计说明。使用这些表述时应结合实际承担的工作；性能、用户数或收益数据仅在具有测量记录后补充。
